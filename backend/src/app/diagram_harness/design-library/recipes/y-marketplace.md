# Recipe Y: Marketplace / Platform

## Quick ref

- **When:** Two-sided markets, directories, aggregators, classifieds, booking platforms, service matching.
- **Token budget:** ~16k (HARNESS + ergonomics + components + page-archetypes + layout + anti-similarity).
- **Files to read:** `09-ergonomics.md`, `04-components.md`, `07-page-archetypes.md` > SaaS, `03-layout.md`
- **Personality fit:** Primary — Professional. Strong — Playful, Luxury, Warm/Human.

## Page flow intent

SERVE BOTH SIDES. The homepage must speak to buyers AND sellers/providers without confusing either.

Core rhythm: `value prop hero (addresses primary side) → search/browse as primary interaction → curated/featured listings → "how it works" for secondary side → trust signals (reviews, transaction count, guarantees) → dual CTAs (browse vs join as provider)`.

The search bar is the most important element — it should feel like a product, not an input field. Study Airbnb's search evolution.

## Techniques

- Split hero: value prop for both sides (buyers + sellers / hosts + guests)
- Category browsing with visual cards
- Search as primary interaction (prominent, auto-suggesting)
- Social proof: "X active sellers" / "Y transactions" metrics
- Featured/curated listings section
- How-it-works: 3-step numbered process (both sides)
- Trust signals: verified badges, reviews, guarantees
- Bento grid for category showcase

## Font direction

Friendly, accessible sans. Must work across diverse content types. Legibility at small sizes for listing details.

## Color

Neutral base that doesn't compete with user-generated content. ONE brand accent for platform actions (book, buy, message). Semantic colors for status (available, sold, pending).

## Motion budget

LOW. Marketplace is utility — users search, compare, transact. Skeleton loading is critical. Smooth filter transitions. No decoration.

## Anti-patterns

One-sided messaging (only talking to buyers OR sellers). Complex onboarding. Poor search experience. Cluttered listing cards.
